# UX Diagnostic & Research Doctrine

UX failures should be diagnosed through:

- behavioral evidence
- workflow analysis
- telemetry interpretation
- systemic pattern recognition
- root-cause tracing

UX problems should not be evaluated through:

- aesthetic intuition
- anecdotal feedback
- isolated opinions
- speculative assumptions

Preserve evidence-oriented reasoning during UX diagnosis.

Avoid symptom-level interpretation detached from behavioral causality.

---

# Diagnostic Principles

## UX Failure Diagnosis Systems

Every UX failure is typically a symptom of:

- cognitive instability
- interaction ambiguity
- trust erosion
- workflow friction
- broken mental models

Root-cause analysis should prioritize systemic behavioral causality over surface-level critique.

---

## Behavior Over Opinion Systems

### Operational Principle

Observed user behavior is more reliable than self-reported explanation.

### Diagnostic Logic

Behavioral telemetry reveals:

- subconscious friction
- hesitation
- expectation mismatch
- workflow instability

User explanations are frequently distorted by:

- post-rationalization
- memory gaps
- social desirability bias

### Evidence Hierarchy

| Evidence Type | Diagnostic Reliability |
|---|---|
| Behavioral telemetry | High |
| Session replay | High |
| Live usability observation | High |
| Self-reported explanation | Moderate |
| Hypothetical preference | Low |

`[Diagnostic Principle: Behavior Over Self-Reported Explanation]`

---

## Metric Triangulation Systems

### Operational Principle

Single metrics rarely provide reliable diagnosis.

### Diagnostic Rule

Use:

- quantitative signals

to identify:

- where friction occurs

and:

- qualitative observation

to identify:

- why friction occurs

### Triangulation Systems

| Signal Type | Diagnostic Purpose |
|---|---|
| Funnel analytics | Friction localization |
| Session replay | Behavioral interpretation |
| Usability testing | Mental-model validation |
| Heatmaps | Attention distribution |
| Surveys | Sentiment context |

`[Diagnostic Failure: Single-Metric Interpretation]`

---

## Silent Failure Detection Systems

### Operational Principle

Task completion does not guarantee healthy UX.

### Hidden Failure Patterns

Users may complete workflows through:

- confusion
- anxiety
- workaround behavior
- inefficient navigation
- learned friction tolerance

### Diagnostic Objective

Detect hidden friction masked by superficial completion metrics.

`[Diagnostic Risk: Hidden Friction Behind Completion Metrics]`

# Root-Cause Analysis Systems

## Root-Cause Diagnosis Doctrine

Visible UX failures are often secondary symptoms.

Root causes frequently originate from:

- broken mental models
- trust instability
- interaction ambiguity
- hierarchy failure
- expectation mismatch

Avoid stopping at symptom-level explanation.

---

## Symptom vs Root-Cause Separation

### Example: Checkout Abandonment

| Layer | Diagnostic Interpretation |
|---|---|
| Symptom | Users abandon checkout at Step 2 |
| False diagnosis | "The form is too long." |
| Root cause | Phone-number collection introduces trust anxiety and unclear value exchange |

---

### Example: Non-Interactive Click Targets

| Layer | Diagnostic Interpretation |
|---|---|
| Symptom | Users repeatedly click a non-interactive element |
| False diagnosis | "Users are confused." |
| Root cause | The element visually mimics actionable affordance systems |

### Diagnostic Rule

Map symptoms to:

- behavioral friction
- cognitive instability
- trust breakdown
- heuristic violations
- expectation mismatch

`[Diagnostic Failure: Surface-Level Interpretation]`

# Usability Testing Intelligence Systems

## Behavioral Observation Doctrine

Usability testing should prioritize behavioral observation rather than opinion collection.

Observe:

- hesitation timing
- recovery behavior
- interaction paths
- expectation mismatch
- workflow instability

---

## Task Observation Systems

### Operational Rule

Assign goals rather than procedural instructions.

Preferred:

- "Find a jacket under $50"

Avoid:

- "Use the price filter."

### Diagnostic Objective

Reveal natural behavioral strategies rather than guided compliance.

`[Research Failure: Instruction-Led Usability Bias]`

---

## Think-Aloud Triangulation Systems

### Operational Principle

Behavioral evidence should override verbal confidence.

### Failure Pattern

Users verbally report:

- "This is easy"

while behaviorally demonstrating:

- hesitation
- workflow instability
- search confusion

### Diagnostic Objective

Separate verbal confidence from observed operational behavior.

`[Diagnostic Conflict: Verbal Confidence vs Behavioral Friction]`

---

## Expectation-Mismatch Detection Systems

### Operational Rule

Before interaction, ask:

> "What do you expect to happen next?"

If system behavior violates prediction:

- the mental model is unstable

### Diagnostic Objective

Detect expectation-model divergence before workflow failure compounds.

`[Mental Model Failure: Prediction Violation]`

# Evidence & Inference Systems

## Evidence-Separation Doctrine

Always distinguish between:

- observed evidence
- inferred conclusions
- assumptions
- heuristics
- speculation

<reasoning_constraints>

Inference should never be presented as verified operational truth.

Estimated confidence, assumed correctness, and speculative causality should remain explicitly separated from:
- observed telemetry
- validated testing
- reproducible behavioral evidence

</reasoning_constraints>

Never present:

- inferred stability
- estimated confidence
- assumed correctness

as verified operational truth.

### Evidence Labeling Systems

Explicitly identify:

- what was tested
- what was conceptually reviewed
- what remains uncertain

`[Research Integrity Failure: Assumption Presented as Verified Truth]`
