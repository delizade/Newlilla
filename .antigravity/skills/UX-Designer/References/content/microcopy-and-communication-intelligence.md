# CTA & Action Language Systems

Users should predict the exact outcome of an action before execution.

Ambiguous wording creates:
- hesitation
- trust erosion
- funnel abandonment
- interaction uncertainty

## Action Certainty & Verb-Driven CTA Architecture

### Healthy CTA Systems

CTAs should begin with:
- explicit verbs
- deterministic actions
- behaviorally clear outcomes

Examples:
- `Create Workspace`
- `Send Invoice`
- `Start Free Trial`

### Failure Patterns

- Generic labels
- Non-committal wording
- Hidden action magnitude
- Behavioral ambiguity

Examples:
- `Submit`
- `Continue`
- `Next`

`[Interaction Hesitation: Non-Deterministic CTA]`  
`[Behavioral Friction: Ambiguous Action Outcome]`

---

## Progressive Commitment & Psychological Escalation

CTA language should match the user’s psychological commitment level.

Low-commitment exploration language should appear before high-friction commitment requests.

### Healthy Commitment Sequencing

Examples:
- `See Pricing`
- `Explore Features`

before:
- `Buy Now`
- `Upgrade`

### Failure Patterns

- Premature commitment escalation
- High-friction conversion pressure
- Value realization bypass
- Early psychological resistance

`[Friction: Premature Commitment Escalation]`  
`[Conversion Resistance: Psychological Escalation Mismatch]`

# Error & Recovery Communication Systems

Error states function as:
- workflow interruptions
- trust tests
- emotional friction points
- recovery intelligence checkpoints

Messaging should:
- reduce frustration
- avoid blame
- preserve trust
- provide immediate recovery guidance

## Blame Avoidance & Trust-Preserving Error Language

### Healthy Error Framing

Use:
- neutral system-oriented framing
- emotionally stable language
- recovery-oriented communication

Examples:
- `This password requires a number`
- `Connection timed out`

### Failure Patterns

- User-blaming language
- accusatory phrasing
- emotionally hostile wording
- responsibility projection

Examples:
- `You entered the wrong password`
- `Invalid input`

`[Behavioral Friction: User-Blaming Language]`  
`[Trust Friction: Accusatory Recovery Messaging]`

---

## Actionable Recovery Communication

Every error should communicate:
- what happened
- why it happened
- how to recover
- what the next step is

### Failure Patterns

- Dead-end messaging
- Technical dumps
- Vague apologies
- Recovery ambiguity
- Contextless failure reporting

Examples:
- `Oops, something went wrong`
- `Error 404: Null Reference`

`[Recovery Failure: Dead-End Error State]`  
`[Workflow Breakdown: Recovery Path Ambiguity]`
